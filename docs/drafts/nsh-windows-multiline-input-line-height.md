# windows: Multiline Input leaves a growing gap below the text

## Description

On Windows, a multiline `Input` uses the configured line height for layout, but the rendered lines do not follow it. The difference accumulates with each added line and leaves a blank area below the last line. A plain `nsh/base` `Input` reproduces this without a `Scroll`, an outer card, or a custom textarea.

## Environment

- NSH: `0.6.1 (2f51d86)`
- Platform: Windows 11, build 26300, at 150% display scaling
- Reproduced with `nsh test --target windows` on the native development host

## Steps to Reproduce

Use this `App.tsx` in an NSH TSX project:

```tsx
import { mount, signal, Text, View } from "nsh";
import { Input } from "nsh/base";

const value = Array(12).fill("The quick brown fox").join("\n");

function App() {
  const inputHeight = signal(0);
  const caretY = signal(0);

  return (
    <View class="flex-1 p-4">
      <Input
        autoFocus
        multiline
        value={value}
        class="w-full text-sm"
        onLayout={({ bounds }) => inputHeight.set(bounds.size.height)}
        onCaretMove={({ bounds }) => caretY.set(bounds.origin.y)}
      />
      <Text>{`Input height: ${inputHeight()} pt; caret Y: ${caretY()} pt`}</Text>
    </View>
  );
}

mount(() => <App />);
```

1. Open the app in a window that fits all 12 lines without wrapping. A 420 × 500 pt window is sufficient.
2. With the input focused, press `Ctrl+Home` and record the caret Y value. Press `Ctrl+End` and record it again. The difference covers 11 line intervals.
3. Change the class to `w-full text-sm leading-8` and repeat step 2.

## Expected

The input uses the same line height for layout and drawing. Adding `leading-8` increases both the input height and the distance between lines.

## Actual

| Input class | Input height | Caret travel over 11 line intervals | Observed line spacing |
| --- | ---: | ---: | ---: |
| `text-sm` | 240 pt | 195.3 pt | 17.8 pt |
| `text-sm leading-8` | 384 pt | 195.3 pt | 17.8 pt |

The input grows by 144 pt, but the distance between lines does not change. The extra height appears below the text.

[PR #891](https://github.com/longbridge/nsh/pull/891) fixed a similar difference between layout and drawing for multiline inputs on Linux. This report concerns Windows.
